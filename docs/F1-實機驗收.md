# F1 自動重連：實機驗收清單

對應 `docs/SPEC-1.3.md` §3.6 驗收條件，以及 §10 的 Q1、Q6。F1 已實作（`dpd_delay = 10s`、`dpd_action = clear`、重送參數 2.0／3／1.5），這份清單用來在實機上確認行為。

## 準備

1. 先把 FortiClient 斷線，用 SplitSwan 連上，並確認「環境檢查」全綠。
2. 開一個終端機視窗，每秒記錄一次狀態（輔助程式可以用 sudo 免密碼執行）：
   ```bash
   while :; do printf '%s  ' "$(date +%T)"; sudo -n /usr/local/libexec/splitswan-helper status; sleep 1; done | tee -a ~/Desktop/f1-status.log
   ```
3. 在「連線」頁展開「連線紀錄」。每做完一項，就把紀錄拷貝下來並註明是第幾項，之後可以用來數連線嘗試次數。

每項都記下三個數字：**開始時間**、**恢復連線（或確認沒有重連）的時間**、**連線嘗試次數**。

## 要回報的數字（規格 Q1、Q6）

- **Q1**：第 5 項中，`status` 有沒有在約 30 秒內從 `connected` 變成非 `connected`。沒有的話，代表 `dpd_action = clear` 沒有移除 SA，要改回 `restart`。
- **Q6**：`test-dpd.sh` 結果中的「偵測到失聯」秒數（規格預估約 26 秒）。另外找時間用手機熱點連線一小時，看連線紀錄裡有沒有非預期的重建。重建頻繁的話，代表重送參數太激進。

## 回報方式

把「結果」欄填好，連同 `~/Desktop/f1-status.log` 和各項的連線紀錄一起給我。**貼上前先把真實的閘道 IP 換掉**。這份清單會進 repo，只記錄結論與秒數，不放原始紀錄。

## 第一輪結果（2026-09-30，1.5.2＋F2）

- **Q1**：通過。封鎖閘道後第 31 秒 `status` 轉為非 connected，`dpd_action = clear` 確實移除 SA，不需改回 `restart`。
- **Q6**：失聯偵測 31 秒（規格預估約 26 秒），在「約 30 秒內」的範圍。熱點下連線一小時的誤判觀察尚未進行。
- **F2 通知**：同一次測試中，約 60 秒內收到一次「已斷線」、封鎖期間未重複，解除後收到「已恢復連線」；手動斷線與睡眠喚醒都沒有通知。
